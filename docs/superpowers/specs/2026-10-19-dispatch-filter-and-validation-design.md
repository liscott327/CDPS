# 跨廠調度單篩選欄位擴充與邊界條件防呆設計規格書

## 1. 概述
本文件針對 CPDS 系統之首頁調度管理畫面 (`CPDS/index.html`) 進行功能擴充與邊界防呆機制強化。包含：
1. 支援調度列表篩選欄位擴充（目的廠多選、調度起訖時間）。
2. 調度列表之「目的廠與支援時段摘要」依篩選條件動態過濾顯示（單獨篩選目的廠時僅呈現符合該目的廠之單筆/多筆明細）。
3. 新增與編輯明細時，阻擋過去之調度日期與時間。
4. 各廠每日限制僅能建立一張調度單，具備即時提示與送出阻擋。

---

## 2. 介面與排版調整 (UI & Layout)

### 2.1 篩選工具列擴充 (`#filterForm`)
將現有的篩選列排版重新調整為響應式網格系統：
- **調度日期(起)** (`#filterStartDate`)：`type="date"`，預設帶入 `2026-10-15`。
- **調度日期(訖)** (`#filterEndDate`)：`type="date"`，預設帶入 `2026-10-16`。
- **來源廠** (`#filterDept`)：Select2 多選下拉選單，選項：`A5-1廠`、`A5-2廠`、`A5-3廠`。
- **目的廠** (`#filterTargetDept`)：新增 Select2 多選下拉選單，選項：`A5-1廠`、`A5-2廠`、`A5-3廠`，預設為空。
- **調度時間(起)** (`#filterStartTime`)：Flatpickr 24小時制時間輸入框 (`H:i`)，預設為空。
- **調度時間(訖)** (`#filterEndTime`)：Flatpickr 24小時制時間輸入框 (`H:i`)，預設為空。
- **關鍵字與操作按鈕**：關鍵字輸入框 (`#filterKeyword`)，搭配「查詢」(`#btnFilterQuery`) 與「重設」(`#btnFilterReset`) 按鈕。

### 2.2 表單編輯區即時提示
在下半部編輯區調度條件列下方，增加重複單據警示容器 (`#duplicatePlanAlert`)：
- 當使用者變更調度日期或來源廠時，若該日期該廠已存在調度單，立即呈現黃色警告框：`⚠️ 已建立過 [日期] [廠別] 的調度單`。

## 3. 查詢篩選與表格摘要渲染 (Logic & Formatter)

### 3.1 支援調度列表過濾邏輯 (`applyMasterFilter`)
每筆主調度單 (`plan`) 必須符合以下所有啟用的篩選條件：
1. **日期區間**：`plan.dispatchDate` 落在 `filterStartDate` 至 `filterEndDate`。
2. **來源廠**：若有選取來源廠，`filterDept.includes(plan.sourceDept)` 必須為 true。
3. **目的廠**：若有選取目的廠，`plan.items` 內至少需有一筆 `targetDept` 包含於所選目的廠清單。
4. **調度時間**：若有填寫調度時間起或訖，`plan.items` 內至少需有一筆明細時段與查詢時段產生重疊（交集）：
   $$\text{item.startTime} < \text{filterEndTime} \quad \land \quad \text{item.endTime} > \text{filterStartTime}$$
5. **關鍵字**：搜尋單據編號、來源廠、目的廠、用途、員工工號與姓名。

### 3.2 「目的廠與支援時段摘要」動態渲染
在主清單的 `summary` 欄位格式化函數 (`formatter`) 中：
- 取得當前作用中的篩選條件：目的廠多選陣列 (`targetDepts`) 與調度時間起訖 (`timeStart`, `timeEnd`)。
- 若有指定目的廠或調度時間，僅將符合該目的廠與時間重疊條件的 `item` 渲染為摘要徽章（Badge）；未符合的明細項目不顯示。
- 若未設定任何目的廠或時間條件，維持顯示所有明細項目。
- 效果：當使用者單獨篩選目的廠（如 `A5-2廠`）時，列表中該列的摘要僅呈現 `A5-2廠 (10:00~11:00) [JM10069] 陳家羚, [JM10099] 張秀燕` 單筆資料。

## 4. 邊界條件與驗證防呆機制 (Validation)

### 4.1 時間判定輔助函數 (`isPastDateTime`)
- 定義函數 `isPastDateTime(dateStr, timeStr)`：
  - 將傳入的日期字串（格式 `YYYY-MM-DD` 或 `YYYY/MM/DD`）與時間字串（`HH:mm`）組合為 JavaScript `Date` 物件。
  - 與執行時的系統時間（`new Date()`）比對。
  - 若組合之時間 `< new Date()`，回傳 `true`（代表已過去）；否則回傳 `false`。

### 4.2 新增子明細防呆 (`#btnAddSubItem`)
- 在驗證表單基本欄位後，呼叫 `isPastDateTime(formData.dispatchDate, formData.startTime)`。
- 若為過去時間：
  - 彈出警告訊息：`「調度開始時間已過去，無法新增過去的明細！」`
  - 中斷新增流程，不寫入 `currentSubItems`。

### 4.3 編輯修改子明細防呆 (`#btnUpdateSubItem`)
- 在點選修改並驗證表單基本欄位後，呼叫 `isPastDateTime(formData.dispatchDate, formData.startTime)`。
- 若修改後之開始時間為過去時間：
  - 彈出警告訊息：`「調度開始時間已過去，無法更新為過去的時間！」`
  - 中斷修改流程，不覆蓋既有明細。

### 4.4 每日每廠僅能建立一調度單防呆
- **即時比對檢核 (`checkDuplicatePlan`)**：
  - 當調度日期 (`#dispatchDate`) 或來源廠 (`#sourceDept`) 變更時觸發。
  - 檢視 `masterDispatchList` 是否已有相同 `dispatchDate` 與 `sourceDept` 的單據。
  - 若當前為編輯模式 (`editingPlanId` 存在)，則排除自身單據。
  - 若已存在，於表單區顯示提示標籤 `已建立過 [日期] [廠別] 的調度單`；若無則隱藏。
- **儲存送出阻擋 (`#btnSubmitPlan`)**：
  - 送出整張調度單前，執行重複檢查。
  - 若重複，彈出 `alert('已建立過 ' + mainDate + ' ' + mainSource + ' 的調度單')`。
  - 中斷送出，不寫入或更新主檔清單。

## 5. 測試與驗證計畫
1. **目的廠多選篩選測試**：
   - 篩選 `A5-2廠`，確認主列表第一列摘要僅顯示 `A5-2廠` 單筆資料，不顯示 `A5-3廠`。
   - 篩選多個目的廠（如 `A5-2廠` + `A5-3廠`），確認符合的明細皆正常呈現。
2. **調度時間篩選測試**：
   - 設定篩選時間 `14:00~16:00`，確認包含 `15:00~17:00` 之單據及摘要正常過濾顯示。
3. **過濾重設測試**：
   - 點擊「重設」，確認目的廠、調度時間、來源廠、日期與關鍵字皆被清空並重載資料。
4. **新增明細過去時間阻擋測試**：
   - 選擇過去日期或今天已過去的開始時間點擊「新增」，確認彈出阻擋訊息且未加入清單。
5. **修改明細過去時間阻擋測試**：
   - 嘗試將明細修改為過去開始時間，確認彈出阻擋訊息且未被修改。
6. **各廠每日一單阻擋測試**：
   - 嘗試在新增模式下填入已存在的日期與廠別（如 `2026-10-16` / `A5-1廠`），確認出現即時警告文字，且點擊「儲存送出」時彈出阻擋視窗。
