# 現場簽到作業 (checkin.html) 異常原因紅框提示與移除操作欄位 設計規格

## 1. 概述
本規格針對現場簽到作業頁面 (`checkin.html`) 進行兩項優化：
1. **異常原因未填寫標記紅框與儲存阻擋**：未填寫原因之輸入框呈現紅色外框，並於使用者點擊「儲存所有異常原因」時進行防呆驗證，若有未填寫項則阻擋儲存並彈出提示。
2. **移除異常標記表格的操作欄位與復原按鈕**：異常標記人員一旦被標記為異常，不在此表格提供「復原」按鈕，同時徹底移除異常標記表格之「操作」欄位。

---

## 2. 需求詳細規格

### 2.1 異常標記表格輸入框紅框警示
1. **渲染初始狀態 (`abnormalReasonFormatter`)**：
   - 當表格渲染或更新時，若人員的異常原因 (`reasonText` / `reason`) 為空字串或僅含空白字元，該 `<input>` 元素自動附加 `is-invalid` class。
2. **即時互動檢核 (`onReasonTextInput`)**：
   - 當使用者在輸入框中鍵入文字時：
     - 若內容去除前後空白後長度大於 0，立即移除 `is-invalid`。
     - 若使用者清空內容（長度為 0），立即添加 `is-invalid`。
   - 同步更新記憶體陣列中的 `reasonText` / `reason` 屬性。
3. **儲存防呆驗證 (`saveAllAbnormal`)**：
   - 使用者點擊「儲存所有異常原因」時，檢查表格內所有的異常原因輸入框。
   - 若存在任一輸入框內容為空：
     - 確保該輸入框加上 `is-invalid`。
     - 自動聚焦至第一個空白的輸入框 (`firstEmptyInput.focus()`)。
     - 顯示紅色警告 Toast 訊息：「請填寫所有人員的異常原因後再進行儲存！」。
     - 終止儲存流程，不向後端發送 `/api/checkin/abnormal-reasons` API 請求。
   - 所有輸入框均有填寫時，才正常呼叫後端 API 儲存。

### 2.2 移除異常標記表格操作欄位與復原功能
1. **表格欄位定義更新**：
   - 在 `#abnormal-table` 的 columns 初始化陣列中，移除 `{ field: 'action', title: '操作', formatter: abnormalActionFormatter, align: 'center' }`。
   - 異常標記表格最終僅保留 6 個欄位：
     1. 來源廠 (`dept`)
     2. 工號 (`id`)
     3. 姓名 (`name`)
     4. 調度時間 (`dispatchTime`)
     5. 狀態 (`status`)
     6. 異常說明 (`reason`)
2. **清除無用方法**：
   - 保留/清理 `abnormalActionFormatter` 與 `restoreAbnormal`，避免全域呼叫殘留。
   - 「待簽到」表格之操作欄（「主管代簽」、「異常標記」）完全不受影響，維持原功能運作。

---

## 3. 測試與驗證計畫
1. **靜態視覺驗證**：
   - 開啟 `checkin.html`，檢視異常標記表格：確認無「操作」欄位與「復原」按鈕。
   - 確認異常原因空白時呈現 Bootstrap 原生紅色外框（`is-invalid`）。
2. **動態輸入驗證**：
   - 在空白的異常輸入框中打字，確認紅色外框立即消失。
   - 將文字刪除清空，確認紅色外框立即重新出現。
3. **儲存防呆驗證**：
   - 當有一項或多項為空時，點擊「儲存所有異常原因」，確認無法送出、Toast 顯示「請填寫所有人員的異常原因後再進行儲存！」且自動聚焦至第一個空白欄位。
   - 當所有欄位均填寫時點擊儲存，確認可順利呼叫 API 並跳出成功 Toast。
